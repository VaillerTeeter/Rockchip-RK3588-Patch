# Rockchip U-Boot 开发工具

本章详细介绍 Rockchip U-Boot 开发过程中涉及的各主要工具，包括固件打包/解包、镜像生成、批量编译、Patch 提交等功能，帮助开发者高效完成固件开发与调试工作。

> **说明**：以下所有工具路径均以 U-Boot 根目录为参考点。

## 工具路径总览

| 工具 | 路径 | 功能概述 |
|------|------|----------|
| **trust_merger** | `../rkbin/tools/trust_merger` | 打包/解包 64 位 trust.img |
| **boot_merger** | `../rkbin/tools/boot_merger` | 打包/解包 Loader 镜像 |
| **loaderimage** | `../rkbin/tools/loaderimage` | 打包/解包 uboot.img 与 32 位 trust.img |
| **resource_tool** | `../rkbin/tools/resource_tool` | 打包/解包 resource.img |
| **mkimage** | `./tools/mkimage` | 生成 SPL 模式的 Loader / IDBLOCK 格式 |
| **stacktrace.sh** | `./scripts/stacktrace.sh` | 调用栈信息解析 |
| **mkbootimg** | `./scripts/mkbootimg` | 打包 Android boot / recovery.img |
| **unpack_bootimg** | `./scripts/unpack_bootimg` | 解包 Android boot / recovery.img |
| **repack-bootimg** | `./scripts/repack-bootimg` | 替换 Android 镜像中的固件内容 |
| **pack_resource.sh** | `./scripts/pack_resource.sh` | 打包充电图片到 resource.img |
| **buildman** | `./tools/buildman/buildman` | 批量编译验证多个平台 |
| **patman** | `./tools/patman/patman` | Patch 检查与 Upstream 提交 |

## 一、trust_merger（64 位 trust.img 打包/解包）

**功能**：根据 ini 配置文件打包 64 位平台的 bl30、bl31、bl32 二进制文件，生成 `trust.img`。支持打包和解包两种操作。

> **说明**：32 位平台的 `trust.img` 使用 **loaderimage** 工具打包，详见第三节。

### 1.1 ini 配置文件

以 `RK3368TRUST.ini` 为例：

```
[VERSION]
MAJOR=1                          # 主版本号
MINOR=0                          # 次版本号

[BL30_OPTION]                    # bl30，目前设置为 MCU bin
SEC=1                            # 存在 BL30 bin
PATH=tools/rk_tools/bin/rk33/rk3368bl30_v2.00.bin
ADDR=0xff8c0000                  # 固件在 DDR 中的加载和运行地址

[BL31_OPTION]                    # bl31，多核和电源管理相关
SEC=1                            # 存在 BL31 bin
PATH=tools/rk_tools/bin/rk33/rk3368bl31-20150401-v0.1.bin
ADDR=0x00008000                  # 固件在 DDR 中的加载和运行地址

[BL32_OPTION]
SEC=0                            # 不存在 BL32 bin

[BL33_OPTION]
SEC=0                            # 不存在 BL33 bin

[OUTPUT]
PATH=trust.img                   # 输出固件名
```

### 1.2 打包命令

**参数说明**：

| 参数 | 必选/可选 | 说明 |
|------|-----------|------|
| `<sha>` | 可选 | SHA 相关参数，参考 `make.sh` |
| `<rsa>` | 可选 | RSA 相关参数，参考 `make.sh` |
| `--size [KB] [count]` | 可选 | 输出文件大小：单份大小（KB）和打包份数。省略时默认单份 2MB，打包 2 份 |
| `[ini file]` | **必选** | ini 配置文件路径 |

**命令格式**：

```
./tools/trust_merger <sha> <rsa> <size> [ini file]
```

**范例**：

```
./tools/trust_merger --rsa 3 --sha 2 ./ RKTRUST/RK3399TRUST.ini
out:trust.img
merge success(trust.img)
```

### 1.3 解包命令

**命令格式**：

```
./tools/trust_merger --unpack [input image]
```

**范例**：

```

## 二、boot_merger（Loader 打包/解包）

**功能**：根据 ini 配置文件打包 Miniloader + DDR Bin + USB Plug，生成 Loader 固件。支持打包和解包两种操作。

> 更多参考：编译烧写章节。

### 2.1 ini 配置文件

以 `RK3288MINIALL.ini` 为例：

```
[CHIP_NAME]
NAME=RK320A                       # 芯片名称："RK"+ 与 maskrom 约定的 4B 芯片型号

[VERSION]
MAJOR=2                           # 主版本号
MINOR=36                          # 次版本号

[CODE471_OPTION]                  # code471，目前设置为 DDR Bin
NUM=1
Path1=tools/rk_tools/bin/rk32/rk3288_ddr_400MHz_v1.06.bin

[CODE472_OPTION]                  # code472，目前设置为 USB Plug Bin
NUM=1
Path1=tools/rk_tools/bin/rk32/rk3288_usbplug_v2.36.bin

[LOADER_OPTION]
NUM=2
LOADER1=FlashData                 # Flash Data，目前设置为 DDR Bin
LOADER2=FlashBoot                 # Flash Boot，目前设置为 Miniloader Bin
FlashData=tools/rk_tools/bin/rk32/rk3288_ddr_400MHz_v1.06.bin
FlashBoot=tools/rk_tools/bin/rk32/rk3288_miniloader_v2.36.bin

[OUTPUT]                          # 输出文件名
PATH=rk3288_loader_v1.06.236.bin
```

### 2.2 打包命令

**参数说明**：

| 参数 | 必选/可选 | 说明 |
|------|-----------|------|
| `[ini file]` | **必选** | ini 配置文件路径 |

**命令格式**：

```
./tools/boot_merger [ini file]
```

**范例**：

```
./tools/boot_merger ./RKBOOT/RK3399MINIALL.ini
out:rk3399_loader_v1.17.115.bin
fix opt:rk3399_loader_v1.17.115.bin
merge success(rk3399_loader_v1.17.115.bin)
```

### 2.3 解包命令

**命令格式**：

```
./tools/boot_merger --unpack [input image]
```

**范例**：

```
./tools/boot_merger --unpack rk3399_loader_v1.17.115.bin
unpack entry(rk3399_ddr_800MHz_v1.17)
unpack entry(rk3399_usbplug_v1.15)
unpack entry(FlashData)
unpack entry(FlashBoot)
unpack success
```

## 三、loaderimage（uboot.img 与 32 位 trust.img 打包/解包）

**功能**：

- 打包 `u-boot.bin` 生成 `uboot.img`
- 打包 32 位平台的 TEE bin 生成 `trust.img`

### 3.1 打包 uboot

**参数说明**：

| 参数 | 必选/可选 | 说明 |
|------|-----------|------|
| `[input bin]` | **必选** | bin 源文件 |
| `[output image]` | **必选** | 输出文件名 |
| `[load_addr]` | **必选** | 加载地址 |
| `--size [KB] [count]` | 可选 | 输出文件大小。省略时默认单份 1MB，打包 4 份 |

**命令格式**：

```
./tools/loaderimage --pack --uboot [input bin] [output image] [load_addr] <size>
```

**范例**：

```
./tools/loaderimage --pack --uboot ./u-boot.bin uboot.img 0x60000000 --size 1024 2
load addr is 0x60000000!
pack input u-boot.bin
pack file size: 701981
crc = 0xc595eb85
uboot version: U-Boot 2017.09-02593-gb6e59d9 (Feb 18 2019 - 13:58:53)
pack uboot.img success!
```

### 3.2 解包 uboot

**命令格式**：

```
./tools/loaderimage --unpack --uboot [input image] [output bin]
```

**范例**：

```
./tools/loaderimage --unpack --uboot uboot.img uboot.bin
unpack input uboot.img
unpack uboot.bin success!
```

### 3.3 打包 trust（32 位平台）

**参数说明**：

| 参数 | 必选/可选 | 说明 |
|------|-----------|------|
| `[input bin]` | **必选** | TEE bin 文件 |
| `[output image]` | **必选** | 输出文件名 |
| `[load_addr]` | **必选** | 加载地址 |
| `--size [KB] [count]` | 可选 | 输出文件大小。省略时默认单份 1MB，打包 4 份 |

**命令格式**：

```
./tools/loaderimage --pack --trustos [input bin] [output image] [load_addr] <size>
```

**范例**：

```
./tools/loaderimage --pack --trustos ./bin/rk32/rk322x_tee_v2.00.bin trust.img 0x80000000 --size 1024 2
load addr is 0x80000000!
pack input bin/rk32/rk322x_tee_v2.00.bin
pack file size: 333896
crc = 0x2de93b46
pack trust.img success!
```

### 3.4 解包 trust（32 位平台）

**命令格式**：

```
./tools/loaderimage --unpack --trustos [input image] [output bin]
```

**范例**：

```
./tools/loaderimage --unpack --trustos trust.img tee.bin
unpack input trust.img
unpack tee.bin success!
```

## 五、mkimage（SPL 模式 Loader 生成）

**功能**：生成 SPL 模式下的 Loader 固件。例如生成 Rockchip BootROM 所需的 **IDBLOCK** 格式，同时修改 `u-boot-tpl.bin` 头部前 4 字节为 BootROM 所需校验的 ID。

> 更多参考：SPL 章节、TPL 章节。

**命令格式**：

```
./tools/mkimage -n <platform> -T rksd -d <input bin> <output image>
```

**范例**：

```
./tools/mkimage -n rk3328 -T rksd -d tpl/u-boot-tpl.bin idbloader.img
```

**详细参考**：

```
./doc/mkimage.1
```

## 六、stacktrace.sh（调用栈解析）

**功能**：将 U-Boot / SPL / TPL 的调用栈地址转换为可读的函数名和代码位置。

> 使用方法与完整原理请参考调试手段章节和平台架构章节的"调用栈回溯"部分。

**命令格式**：

```
./scripts/stacktrace.sh ./dump.txt       # 解析来自 U-Boot 的调用栈
./scripts/stacktrace.sh ./dump.txt tpl   # 解析来自 TPL 的调用栈
./scripts/stacktrace.sh ./dump.txt spl   # 解析来自 SPL 的调用栈
```

> **注意**：执行该命令时，当前机器上的固件必须和当前代码环境匹配，否则会得到错误的转换结果。

## 七、mkbootimg（打包 Android boot / recovery.img）

**功能**：打包 Android 工程中的 Kernel、Resource、Ramdisk 生成 `boot.img` 或 `recovery.img`。

> 更多参考：平台架构章节的"Kernel 镜像格式"部分。

**范例**：

```
./scripts/mkbootimg --kernel zImage --second resource.img --ramdisk ramdisk.img --out boot.img
```

## 八、unpack_bootimg（解包 Android boot / recovery.img）

**功能**：解包 `boot.img` 或 `recovery.img`，提取其中的 Kernel、Resource、Ramdisk 等固件。

**范例**：

```
./scripts/unpack_bootimg --boot_img boot.img --out out/
```

## 九、repack-bootimg（替换 Android 镜像内固件）

**功能**：替换 `boot.img` 或 `recovery.img` 中指定的固件内容（如 Kernel、Resource），无需完整重新打包。

**范例**：

```
# 仅替换 kernel
./scripts/repack-bootimg --boot_img boot.img --kernel zImage -o boot_repack.img

# 仅替换 resource
./scripts/repack-bootimg --boot_img boot.img --second resource.img -o boot_repack.img
```

## 十一、buildman（批量编译）

**功能**：批量编译代码，用于验证当前平台的提交是否影响其他平台。非常适合做多平台兼容性检查。

### 11.1 环境配置

使用 buildman 需要提前设置好 toolchain 路径，编辑 `~/.buildman` 文件：

```
[toolchain]
arm: ~/prebuilts/gcc/linux-x86/arm/gcc-linaro-6.3.1-2017.05-x86_64_arm-linux-gnueabihf/
aarch64: ~/prebuilts/gcc/linux-x86/aarch64/gcc-linaro-6.3.1-2017.05-x86_64_aarch64-linux-gnu/
```

### 11.2 基本用法

**编译所有 Rockchip 平台的 U-Boot**：

```
./tools/buildman/buildman rockchip
```

**理想输出**：

```
$ ./tools/buildman/buildman rockchip
boards.cfg is up to date. Nothing to do.
Building current source for 34 boards (4 threads, 1 job per thread) 34 0 0 /34 evb-rk3326
```

**结果解读**：

显示结果中，三个数字依次表示：

| 数字 | 颜色 | 含义 |
|------|------|------|
| 第一个 | 绿色 | 编译完全 pass 的平台数量 |
| 第二个 | 黄色 | 含 warning 输出的平台数量 |
| 第三个 | 红色 | 有 error 无法编译通过的平台数量 |

编译过程中如有 warning 或 error 会在终端上详细显示。

### 11.3 详细参考

```

## 十二、patman（Patch 检查与提交）

**功能**：Python 实现的 Patch 管理工具，通过调用 checkpatch 等工具完成 Patch 的检查与提交，是做 Patch Upstream（U-Boot、Kernel）的必备工具。

**主要功能**：

- 根据参数自动 format 补丁
- 调用 checkpatch 进行检查
- 从 commit 信息提取并转换成 Upstream Mailing List 所需的 Cover-letter、patch version、version changes 等信息
- 自动去掉 commit 中的 Change-Id
- 自动根据 Maintainer 和文件提交信息提取每个 Patch 所需的收件人
- 根据 `~/.gitconfig` 或 `./.gitconfig` 配置把所有 Patch 发送出去

### 12.1 命令选项

使用 `-h` 选项查看所有命令选项：

```
$ patman -h
Usage: patman [options]

Create patches from commits in a branch, check them and email them
as specified by tags you place in the commits. Use -n to do a dry run first.

Options:
    -h, --help show this help message and exit
    -H, --full-help Display the README file
    -c COUNT, --count=COUNT Automatically create patches from top n commits
    -i, --ignore-errors Send patches email even if patch errors are found
    -m, --no-maintainers Don't cc the file maintainers automatically
    -n, --dry-run Do a dry run (create but don't email patches)
    -p PROJECT, --project=PROJECT Project name; affects default option values
                                 and aliases [default: u-boot]
    -r IN_REPLY_TO, --in-reply-to=IN_REPLY_TO
                                 Message ID that this series is in reply to
    -s START, --start=START Commit to start creating patches from (0 = HEAD)
    -t, --ignore-bad-tags Ignore bad tags / aliases
    --test run tests
    -v, --verbose Verbose output of errors and warnings
    --cc-cmd=CC_CMD Output cc list for patch file (used by git)
    --no-check Don't check for patch compliance
    --no-tags Don't process subject tags as aliases
    -T, --thread Create patches as a single thread
```

### 12.2 常用选项

| 选项 | 说明 |
|------|------|
| `-t` | 标题中 `":"` 前面的都当成 TAG，大部分无法被 patman 识别，需要使用此选项 |
| `-i` | 如果有些 warning（如超过 80 个字符）无需解决，可直接加此选项提交补丁 |
| `-s` | 如果要提交的补丁不在当前 tree 的 top，可通过此选项跳过 top 的 N 个补丁 |
| `-n` | 如果只想校验最新补丁是否可通过 checkpatch 而不提交，可使用此选项 |

### 12.3 典型用例

**提交最新的 3 个 Patch**：

```
patman -t -c3
```

> 命令运行后 checkpatch 如果有 error 或 warning 会自动 abort，需要修改解决 Patch 问题后重新运行。

### 12.4 Commit Message 规范

patman 配合 commit message 中的关键字可以生成 Upstream Mailing List 所需的信息。

**典型的 commit 示例**：

```
commit 72aa9e3085e64e785680c3fa50a28651a8961feb
Author: Kever Yang <kever.yang@rock-chips.com>
Date: Wed Sep 6 09:22:42 2017 +0800

    spl: add support to booting with OP-TEE

    OP-TEE is an open source trusted OS, in armv7, its loading and
    running are like this:
    loading:
    - SPL load both OP-TEE and U-Boot
    running:
    - SPL run into OP-TEE in secure mode;
    - OP-TEE run into U-Boot in non-secure mode;

    More detail:
    <https://github.com/OP-TEE/optee_os> and search for 'boot arguments'
    for detail entry parameter in:
    core/arch/arm/kernel/generic_entry_a32.S

    Cover-letter:
    rockchip: add tpl and OPTEE support for rk3229

    Add some generic options for TPL support for arm 32bit, and then
    TPL support for rk3229(cortex-A7), and then add OPTEE support
    in SPL.

    Tested on latest u-boot-rockchip master.

    END

    Series-version: 4
    Series-changes: 4
    - use NULL instead of '0'
    - add fdt_addr as arg2 of entry

    Series-changes: 2
    - Using new image type for op-tee

    Change-Id: I3fd2b8305ba8fa9ea687ab7f3fd1ffd2fac9ece6
    Signed-off-by: Kever Yang <kever.yang@rock-chips.com>
```

**Commit Message 关键字说明**：

| 关键字 | 说明 |
|--------|------|
| `Cover-letter: <title>` | 生成 Cover-letter 的标题和内容 |
| `Series-version: <N>` | 指定 Patch 版本号 |
| `Series-changes: <N>` | 记录各版本的改动 |
| `Series-prefix: <prefix>` | 自定义邮件主题前缀 |
| `Series-cc: <email>` | 额外抄送列表 |
| `END` | Cover-letter 内容结束标记 |

patman 发送这个 Patch 时会自动生成 Cover-letter：

```
[PATCH v4 00/11] rockchip: add tpl and OPTEE support for rk3229
```

对应 Patch 的标题包含版本信息和在整个 Series 中的序号：

```
[PATCH v4,07/11] spl: add support to booting with OP-TEE
```

最终收件人收到的 Patch 邮件中：Change-Id 自动去除、Cover-letter 内容自动剥离、Version-changes 信息自动转换为非正文信息。
