# Rockchip U-Boot 编译与烧写

本章介绍 Rockchip U-Boot 的编译环境搭建、固件编译流程、烧写方法及特殊打包操作。

## 一、前期准备

### 1.1 工具链与依赖

U-Boot 编译依赖以下两个外部仓库，均需与 U-Boot 工程保持**同级目录关系**：

| 依赖 | 说明 | 下载方式 |
|------|------|----------|
| **rkbin** | Rockchip 闭源 binaries、脚本、打包工具。编译时自动索引相关文件，打包生成 loader、trust、uboot 固件。 | 参考附录章节 |
| **GCC** | 编译器使用 `gcc-linaro-6.3.1`，放置于 `prebuilts` 目录内。 | 参考附录章节 |

GCC 工具链的目录结构如下：

```
// 32 位平台
prebuilts/gcc/linux-x86/arm/gcc-linaro-6.3.1-2017.05-x86_64_arm-linux-gnueabihf

// 64 位平台
prebuilts/gcc/linux-x86/aarch64/gcc-linaro-6.3.1-2017.05-x86_64_aarch64-linux-gnu/
```

### 1.2 选择 defconfig

各平台的 defconfig 文件位于 `./configs/` 目录下，用户根据目标平台选择对应文件进行编译。具体平台的 defconfig 定义请参考"平台架构"章节。

### 1.3 Config Fragment（配置片段）

由于单个平台可能存在多种产品的差异化需求，单一的 defconfig 已经无法完全满足。从 **RV1126** 开始，Rockchip 引入了 **Config Fragment** 机制，即对 defconfig 进行 overlay 叠加。

**工作原理**：以 `rv1126-emmc-tb.config` 为例，其在文件内通过 `CONFIG_BASE_DEFCONFIG="rv1126_defconfig"` 指定基础 defconfig。执行以下命令时：

```
./make.sh rv1126-emmc-tb
```

U-Boot 会先用 `rv1126_defconfig` 生成 `.config`，再使用 `rv1126-emmc-tb.config` 中的配置对 `.config` 进行 overlay。该命令等效于：

```
make rv1126_defconfig rv1126-emmc-tb.config && make
```

**更新 Config Fragment**：如需更新 config fragment 文件，借助 `./scripts/sync-fragment.sh` 脚本，将当前 `.config` 与基础 defconfig 的差异项 diff 到 config fragment 文件中：

```
./scripts/sync-fragment.sh configs/rv1126-emmc-tb.config
```

## 二、固件编译

### 2.1 编译命令

**基本命令**：

```
./make.sh [board]   # [board] 对应 configs/[board]_defconfig 文件
```

**首次编译**：无论 32 位还是 64 位平台，第一次编译或需要重新指定 defconfig 时，编译命令**必须指定** `[board]` 参数：

```
./make.sh rk3399             # 编译 rk3399_defconfig
./make.sh evb-rk3399         # 编译 evb-rk3399_defconfig
./make.sh firefly-rk3288     # 编译 firefly-rk3288_defconfig
```

**二次编译**：如果基于当前 `.config` 再次编译（不更换 defconfig），则无需指定 `[board]`：

```
./make.sh
```

> **注意**：如编译过程中出现异常导致编译失败，请尝试执行 `make distclean` 后重新编译。

### 2.2 编译产物

编译完成后，U-Boot 在根目录下打包生成三个核心固件：

| 固件 | 文件名示例 | 说明 |
|------|-----------|------|
| **uboot.img** | `uboot.img` | U-Boot 本体镜像 |
| **trust.img** | `trust.img` | Trusted-OS 镜像（FIT 格式时无此文件，Trust 二进制打包在 `uboot.img` 内） |
| **loader** | `rk3126_loader_v2.09.247.bin` | Pre-loader 镜像（DDR Bin + Miniloader 或 TPL + SPL） |

以下为编译完成后典型的打包输出信息：

```
// uboot 打包过程

pack file size: 478737
crc = 0x840f163c

pack uboot okay! Input: u-boot.bin

// loader 打包过程及引用的 ini 文件
out:rk3126_loader_v2.09.247.bin

merge success(rk3126_loader_v2.09.247.bin)
pack loader okay! Input: /home/cjh/rkbin/RKBOOT/RK3126MINIALL.ini

// trust 打包过程及引用的 ini 文件

```

> **说明**：即使 `trust.img` 和 loader 打包失败，最后仍会打印编译成功提示——这意味着至少 `uboot.img` 已成功生成。

> **固件打包工具**：详见"工具"章节。

## 三、固件烧写

### 3.1 烧写工具与模式

**烧写工具**：Windows 和 Linux 平台的固件烧写工具建议使用 SDK 发布的工具版本或最新版本。

**烧写模式**：RK 平台共有两种烧写模式：

| 模式 | 说明 |
|------|------|
| **Maskrom 模式** | 最底层的烧写模式，由 BOOTROM 直接进入，即使固件损坏也可烧写 |
| **Loader 模式（U-Boot）** | 在 U-Boot 运行状态下进入的烧写模式 |

### 3.2 进入烧写模式

| 目标模式 | 进入方法 |
|----------|----------|
| **Loader 模式** | ① 开机时，机器**长按音量+**<br>② 开机时，上位机**长按 Ctrl + D** 组合键<br>③ U-Boot 命令行输入：`download` 或 `rockusb 0 $devtype $devnum` |
| **Maskrom 模式** | ① 开机时，上位机**长按 Ctrl + B** 组合键<br>② U-Boot 命令行输入：`rbrom` |

> **说明**：热键触发可能需要多次尝试；启用 Secure-Boot 时无效。

### 3.3 分区表注意事项

U-Boot 目前支持两种分区表格式：**RK Parameter 分区表**（旧）和 **GPT 分区表**（新）。

- 如需从当前分区表类型切换到另一种，**NAND 机器必须整套固件重新烧写**；eMMC 机器支持单独替换分区表
- 如果机器上同时存在两种分区表，**优先识别 GPT 分区表**

可通过开机信息确认当前分区表类型：

```
PartType: EFI      // 当前为 GPT 分区表
PartType: RKPARM   // 当前为 RK Parameter 分区表
```

## 四、固件大小与特殊打包

### 4.1 固件大小

各固件的单份大小和打包份数参考"平台架构"章节（RK 架构 → U-Boot 镜像格式 → 备份打包）。

### 4.2 独立打包命令

`./make.sh` 除了编译代码外，还集成了固件打包功能。以下独立打包命令供开发者在已有编译产物的基础上使用（**前提是已编译过一次 U-Boot**）：

**非 FIT 格式**：

```
./make.sh trust                 # 打包 trust
./make.sh loader                # 打包 loader
./make.sh trust <ini-file>      # 打包 trust 时指定 ini 文件，否则使用默认 ini
./make.sh loader <ini-file>     # 打包 loader 时指定 ini 文件，否则使用默认 ini
```

**FIT 格式**：

```
# 旧脚本
./make.sh spl             # 用 TPL + SPL 替换 DDR Bin 和 Miniloader，打包成 loader
./make.sh spl-s           # 用 SPL 替换 Miniloader，打包成 loader

# 新脚本
./make.sh --spl           # 用 SPL 替换 Miniloader，打包成 loader
./make.sh --tpl           # 用 TPL 替换 DDR Bin，打包成 loader
./make.sh --tpl --spl     # 用 TPL + SPL 替换 DDR Bin + Miniloader，打包成 loader
./make.sh --spl-new       # 比 --spl 多一步重新编译再打包
```

> **如何鉴别新旧脚本**：如果 `--spl` / `--tpl` 等新命令生效，则说明 `make.sh` 为新脚本。

> **更多打包与调试命令参考**：详见"平台架构"章节（RK 架构 → Make.sh 编译与调试工具）。

## 五、SDK 兼容性

### 5.1 androidboot.mode 兼容

低于 Android 8.1 的 SDK 版本，U-Boot 必须开启如下配置才能正常启动 Android：

### 5.2 misc 分区 BCB 偏移兼容

**BCB**（Bootloader Control Block）存放在 `misc.img` 中，是 U-Boot 与 Android 之间用于控制启动流程的交互机制。

由于 Rockchip 平台的历史原因，不同 Android SDK 版本对 BCB 在 misc 分区中的存储偏移有不同的要求：

| Android SDK 版本 | BCB 偏移位置 |
|------------------|-------------|
| >= Android 10.0 | misc 分区偏移 **0** 处 |
| < Android 10.0 | misc 分区偏移 **16KB** 处 |

用户拿到发布的 SDK 后不需要额外处理，U-Boot 会自适应兼容两种偏移位置。

> **警告**：如果拿不同 SDK 版本的 `misc.img` 混用，则可能出现兼容性问题。典型现象为 Android 会一直进入 Recovery 模式。

> 更多 BCB 机制及相关参数请参考"系统模块"章节（Android BCB 部分）。
