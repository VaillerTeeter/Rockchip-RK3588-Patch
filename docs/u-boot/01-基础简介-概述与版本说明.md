# Rockchip U-Boot v2017 基础简介

## 一、概述

### 1.1 功能特性

v2017（next-dev）是 Rockchip 从 U-Boot 官方 v2017.09 正式版本中切出并持续开发的版本，目前已支持 Rockchip 所有主流在售芯片。主要功能包括：

- 支持 Rockchip Android 固件启动
- 支持 Android AOSP 固件启动
- 支持 Linux Distro 固件启动
- 支持 Rockchip Miniloader 和 SPL/TPL 两种 Pre-loader 引导方式
- 支持 LVDS、EDP、MIPI、HDMI、CVBS、RGB 等显示设备
- 支持 eMMC、NAND Flash、SPI NAND Flash、SPI NOR Flash、SD 卡、U 盘等存储设备启动
- 支持 FAT、EXT2、EXT4 文件系统
- 支持 GPT、RK parameter 分区表
- 支持开机 LOGO、充电动画、低电管理、电源管理
- 支持 I2C、PMIC、CHARGE、FUEL GAUGE、USB、GPIO、PWM、GMAC、eMMC、NAND、Interrupt 等外设驱动
- 支持 Vendor Storage，用于保存用户数据和配置
- 支持 RockUSB 和 Google Fastboot 两种 USB Gadget 烧写 eMMC
- 支持 Mass Storage、Ethernet、HID 等 USB 设备
- 支持通过硬件状态动态选择 Kernel DTB

### 1.2 版本说明

Rockchip 的 U-Boot 共有两个版本：**v2014**（旧版本）和 **v2017**（新版本），内部分支名分别为 `rkdevelop` 和 `next-dev`。

用户可通过以下两种方式确认当前 U-Boot 是否为 v2017 版本：

**方式一：查看根目录 Makefile 的版本号。**

```
#
# SPDX-License-Identifier: GPL-2.0+
#
VERSION = 2017
PATCHLEVEL = 09
SUBLEVEL =
EXTRAVERSION =
NAME =
......
```

**方式二：查看开机第一行正式打印信息。**

```
U-Boot 2017.09-01818-g11818ff-dirty (Nov 14 2019 - 11:11:47 +0800)
......
```

- **项目开源**：v2017 已开源并定期更新至 GitHub：<https://github.com/rockchip-linux/u-boot>
- **内核版本要求**：v2017 要求 Rockchip 内核版本 >= 4.4

## 二、核心架构

### 2.1 Driver Model（DM）

DM（Driver Model）是 U-Boot 标准的 device driver 开发模型，与 Kernel 的 device driver 模型非常相似。v2017 版本完全遵循 DM 框架开发各功能模块。建议读者先阅读 U-Boot 官方 DM 文档，了解其架构原理和实现。

> **DM 官方文档**
>
> ```
> ./doc/driver-model/README.txt
> ```

**核心术语（摘自 U-Boot 文档）**

> - **Uclass** — a group of devices which operate in the same way. A uclass provides a way of accessing individual devices within the group, but always using the same interface. For example, a GPIO uclass provides operations for get/set value. An I2C uclass may have 10 I2C ports, 4 with one driver, and 6 with another.
> - **Driver** — some code which talks to a peripheral and presents a higher-level interface to it.
> - **Device** — an instance of a driver, tied to a particular port or peripheral.

**简要概括**

| 概念 | 含义 |
|------|------|
| **Uclass** | 设备驱动模型（一类设备的抽象接口） |
| **Driver** | 驱动（操作外设的代码） |
| **Device** | 设备（驱动的实例，绑定到具体端口或外设） |

**核心代码路径**

```
./drivers/core/
```

### 2.2 安全模型（Security）

在 ARM TrustZone 安全体系中，U-Boot 处于 **Non-Secure World**，无法直接访问任何安全资源（如安全内存、安全 OTP、eFuse 等），需要借助 Trust（ATF/OP-TEE）间接访问。

Rockchip 平台上 U-Boot 的 CPU 运行模式：

```
32 位平台：Non-Secure PL1
64 位平台：EL2（始终为 Non-Secure）
```

### 2.3 U-Boot 设备树（DTS）

U-Boot 拥有自己的 DTS 文件，编译时会自动生成相应的 DTB 文件，附加在 `u-boot.bin` 末尾。

```
源码目录：arch/arm/dts/
```

各平台具体使用的 DTS 文件，通过 defconfig 中的 `CONFIG_DEFAULT_DEVICE_TREE` 指定。

### 2.4 代码重定位（Relocation）

开机阶段，U-Boot 由前一级 Bootloader 加载到 DRAM 的低地址。U-Boot 完成 `board_f.c` 流程后，会将自己重定位到内存末尾某个预留地址上（称为 **Relocation**，具体地址由 U-Boot 内存布局决定），随后继续执行 `board_r.c` 流程。

可通过开机信息识别 Relocation 偏移：

```
U-Boot 2017.09-gabfd1c5e3d-210202-dirty #cjh (Mar 08 2021 - 16:57:31 +0800)
Model: Rockchip RK3568 Evaluation Board
PreSerial: 2, raw, 0xfe660000
DRAM:  2 GiB
Sysmem: init
Relocation Offset: 7d304000, fdt: 7b9f8ed8   ← 偏移到了 DDR 首地址 + 0x7d304000
Using default environment
......
```

> `Relocation Offset` 为 0 表示未发生重定位。

## 三、启动流程

### 3.1 启动顺序（Boot-order）

Rockchip 平台根据前级 Loader 代码是否开源，目前有两套启动方式：

```
// 前级 Loader 闭源（使用 Rockchip 闭源 binaries）
BOOTROM → DDR Bin → Miniloader → TRUST → U-Boot → Kernel

// 前级 Loader 开源（全部源码编译）
BOOTROM → TPL → SPL → TRUST → U-Boot → Kernel
```

其中：
- **TPL** 功能等价于 **DDR Bin**（负责 DDR 初始化）
- **SPL** 功能等价于 **Miniloader**（负责系统 lowlevel 初始化和后级固件加载）
- TPL + SPL 组合实现了与闭源 DDR Bin + Miniloader 一致的功能，可互相替换

### 3.2 TPL / SPL / U-Boot Proper

U-Boot 通过不同的编译条件，可以用同一套代码获取三种不同功能的 Loader：**TPL**、**SPL** 和 **U-Boot Proper**。

| 阶段 | 运行位置 | 职责 |
|------|----------|------|
| **TPL**（Tiny Program Loader） | SRAM | 负责完成 DDR 初始化 |
| **SPL**（Secondary Program Loader） | DDR | 负责完成系统 lowlevel 初始化、加载后级固件（`trust.img` 和 `uboot.img`） |
| **U-Boot Proper** | DDR | 即通常所说的"U-Boot"，负责引导 Kernel |

> **说明**：U-Boot Proper 这一说法主要是为了和 SPL 区分开。出于习惯，后续章节提到的 U-Boot Proper 我们都简称为 **U-Boot**。

完整启动流程：

```
BOOTROM → TPL（DDR Bin）→ SPL（Miniloader）→ TRUST → U-Boot → Kernel
```

> 更多参考：`doc/README.TPL` 和 `doc/README.SPL`

### 3.3 启动命令（Boot Command）

U-Boot 最终通过 `CONFIG_BOOTCOMMAND` 定义的启动命令引导 Kernel。在执行该命令之前，还会先执行 `CONFIG_PREBOOT` 预启动命令（通常定义为空）。

## 四、开发参考

### 4.1 驱动探测（Driver Probe）

U-Boot 虽然引入了 device driver 开发模型，但初始化阶段不会像 Kernel 那样自动发起已注册 device driver 的 probe。Driver 的 probe **必须由用户主动调用**发起。

主要接口如下：

```
int uclass_get_device(enum uclass_id id, int index, struct udevice **devp);
int uclass_get_device_by_name(enum uclass_id id, const char *name, struct udevice **devp);
int uclass_get_device_by_seq(enum uclass_id id, int seq, struct udevice **devp);
int uclass_get_device_by_of_offset(enum uclass_id id, int node, struct udevice **devp);
int uclass_get_device_by_ofnode(enum uclass_id id, ofnode node, struct udevice **devp);
int uclass_get_device_by_phandle_id(enum uclass_id id, int phandle_id, struct udevice **devp);
int uclass_get_device_by_phandle(enum uclass_id id, struct udevice *parent, struct udevice **devp);
int uclass_get_device_by_driver(enum uclass_id id, const struct driver *drv, struct udevice **devp);
int uclass_get_device_tail(struct udevice *dev, int ret, struct udevice **devp);
......
```

上述接口最终都会调用核心函数：

```
int device_probe(struct udevice *dev);  // 建议用户务必了解其内部实现！
```

### 4.2 命令行（Shell / CLI）

U-Boot 的 Shell 称为 **CLI**（Command Line Interface），即命令行模式。用户可以根据需求自定义 CMD。CMD 除了通过 Shell 交互式调用外，还能以代码形式调用：

```
int run_command(const char *cmd, int flag);
int run_command_list(const char *cmd, int len, int flag);
```

### 4.3 编译产物（Build Output）

U-Boot 编译成功后，会在根目录下生成以下重要文件（仅当启用 TPL/SPL 编译时才会生成对应阶段的文件）：

**U-Boot 阶段**

| 文件 | 说明 |
|------|------|
| `u-boot.map` | MAP 表文件 |
| `u-boot.sym` | SYMBOL 表文件 |
| `u-boot` | ELF 文件（类比内核的 `vmlinux`，**重要**） |
| `u-boot.dtb` | U-Boot 自身的 DTB 文件 |
| `u-boot.bin` | 可执行二进制文件，会被打包成 `uboot.img` 用于烧写 |

**SPL 阶段**（路径：`./spl/`）

| 文件 | 说明 |
|------|------|
| `u-boot-spl.map` | MAP 表文件 |
| `u-boot-spl.sym` | SYMBOL 表文件 |
| `u-boot-spl` | ELF 文件（类比内核的 `vmlinux`，**重要**） |
| `u-boot-spl.dtb` | SPL 自身的 DTB 文件 |
| `u-boot-spl.bin` | 可执行二进制文件，会被打包成 Loader 用于烧写 |

**TPL 阶段**（路径：`./tpl/`）

| 文件 | 说明 |
|------|------|
| `u-boot-tpl.map` | MAP 表文件 |
| `u-boot-tpl.sym` | SYMBOL 表文件 |
| `u-boot-tpl` | ELF 文件（类比内核的 `vmlinux`，**重要**） |
| `u-boot-tpl.dtb` | TPL 自身的 DTB 文件 |
| `u-boot-tpl.bin` | 可执行二进制文件，会被打包成 Loader 用于烧写 |

### 4.4 环境变量（Environment Variables）

ENV（Environment Variables）是 U-Boot 支持的一种全局数据管理和传递方式。其原理是构建一张 HASH 映射表，将用户数据以"键值-数据"作为表项进行管理。

ENV 通常用于定义平台配置参数，例如：固件加载地址、网络配置（`ipaddr`、`serverip`）、`bootcmd`、`bootargs` 等。用户可以在命令行下使用 `printenv` 命令查看所有环境变量。

**注意事项**

- 用户可选择是否将 ENV 数据保存到本地存储
- ENV 数据仅限于 U-Boot 内部使用，无法直接传递给内核，内核也无法直接解析
- 用户层可以通过 U-Boot 提供的 `fw_printenv` 工具访问 ENV 数据

**Rockchip 平台 ENV 存储地址和大小定义**

```
// 单位：字节
if ARCH_ROCKCHIP
config ENV_OFFSET
	hex
	depends on !ENV_IS_IN_UBI
	depends on !ENV_IS_NOWHERE
	default 0x3f8000
	help
		Offset from the start of the device (or partition)
config ENV_SIZE
	hex
	default 0x8000
	help
		Size of the environment storage area
endif
```

即：ENV 偏移量默认 `0x3f8000`（约 4MB 偏移），大小默认 `0x8000`（32KB）。

## 五、下载地址

### 5.1 rkbin

rkbin 是 Rockchip 闭源固件与打包工具的集合仓库，U-Boot 编译时依赖此仓库完成 loader、trust、uboot 固件的打包。

| 用户类型 | 获取方式 |
|----------|----------|
| **RK 内部工程师** | 登录 Gerrit 搜索仓库：`rk/rkbin` |
| **外部工程师** | 方式一：下载 RK 发布的完整 SDK<br>方式二：GitHub 下载 <https://github.com/rockchip-linux/rkbin> |

> rkbin 需要与 U-Boot 工程保持同级目录放置，编译脚本 `make.sh` 会自动索引其中的 binaries 和打包工具。

### 5.2 GCC 工具链

U-Boot 编译需要使用 Linaro GCC 6.3.1 版本的工具链，放置于 `prebuilts` 目录内。

| 用户类型 | 获取方式 |
|----------|----------|
| **RK 内部工程师** | 登录 Gerrit 搜索仓库：`gcc-linaro-6.3.1` |
| **外部工程师** | 方式一：下载 RK 发布的完整 SDK（已预置）<br>方式二：前往 [Linaro 官网](https://releases.linaro.org) 下载 |
